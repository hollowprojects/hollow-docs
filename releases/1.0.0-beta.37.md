# 1.0.0-beta.37 — Companions and seams behave

Fixes for a handful of Desk bugs that were found by reading the code during the recent
restructuring. None had been reported, but each was real.

## What's new

- **Hide companion works with three or four panes.** If the companion (Day, Task, Habit or
  Properties) was in a pane that was not beside the one you were in, **Hide companion** opened a
  second companion or did nothing. It now hides the one that is on screen.
- **No more duplicate companions.** Asking for the Day or a note's Properties when one was
  already open could open a second copy, from three places: the command palette's
  "Day / Properties to the side / below", a tab's right-click **Properties** rows, and
  **Properties** in the notes tree's right-click menu. All three now bring the open one forward
  or point it at the new note.
- **Reset to layout is offered only when it is safe.** Right-clicking the seam between panes
  offers **Reset to layout**. If you had added or removed panes since opening the layout, it
  used to apply the layout's sizes to the wrong panes. It is now greyed out unless the desk
  still has the layout's shape.
- **One message, not two,** when templates fail to load as the app starts.

## What to test

- Make three panes (Layout → Three panes). Open the Day in one, click into a pane that is not
  next to it, and use that pane's `⋯` menu → **Hide companion**. The Day should close and no
  second one should open.
- With a note's Properties open, right-click a different note in the sidebar → **Properties**.
  The open Properties should switch to that note; there should still be one.
- Open the Day, then from the command palette choose "Day to the side". Still one Day.
- Open a layout, right-click a seam: **Reset to layout** is available. Add a pane, right-click a
  seam again: it is greyed out.
- Dragging a tab onto the edge of a pane still splits; dropping it on a tab strip still moves it.

## Known issues

- The open items from beta.19 still stand.
