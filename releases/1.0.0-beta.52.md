# 1.0.0-beta.52 — Journal days that fail to open, and a few desk fixes

## What's new

- **A journal day that cannot be opened now says so.** Before, the previous day's page stayed
  on screen under the new day's date, with no error. Now you see an error with **Try again**,
  and it names the day in your Date format ("Could not open the page for 07/03/2026.").
- After such a failure, the sidebar's OPEN marker and `Ctrl+N`'s "beside this note" no longer
  point at the previous day's page.
- **With the same screen open in two panes**, re-opening it from the pane you are in stays in
  that pane instead of jumping to the other one.
- **New note on the empty Notes screen** behaves exactly like `Ctrl+N`, and a create that fails
  says so instead of doing nothing.
- Under the hood: some leftover state was removed, and making a note from a template reads the
  notes tree once instead of twice.

## What to test

- Today: step through days with the arrows, jump to a day from the calendar, from a date link
  in a note, and from the command palette. Each lands on the right day's page.
- Open Planner in two panes. In the right-hand pane, click **List** in the sidebar: the right
  pane changes, not the left.
- Close every note so the Notes screen is empty, then press **New note**: a new note opens.
- Make a note from a template from the picker.
- Archive a pinned project: it leaves the sidebar's pins.

## Known issues

- The open items from beta.19 still stand.
