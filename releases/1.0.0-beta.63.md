# 1.0.0-beta.63 — Measuring Hollow on a large vault

Nothing in this release changes what you see. It adds the tools to measure how Hollow behaves
with years of notes and tasks in it, and records the first measurement.

## What's new

- For people working on Hollow's code: a development build can now start straight on one of
  the sample datasets, so the large one can be timed from a cold start, and there are ready-made
  launch settings for opening each dataset on its own scratch profile.
- For people working on Hollow's code: a timing script measures how long the app's main lists,
  searches and start-up take on the large sample. The first results are written up, and show
  nothing slow yet: no list takes longer than a quarter of a second on a vault of about 3,000
  notes and 4,000 tasks. They also show one read that sends far more text than it needs to,
  which is the first thing to look at if anything gets slow.

All of this exists only in development builds, so the copy of Hollow you test with has nothing
new to see.

## What to test

- Nothing new. Use Hollow as you normally do: open today's page, add and complete a task, keep a
  habit, and check sync still settles if you are signed in.

## Known issues

- The open items from beta.19 still stand.
