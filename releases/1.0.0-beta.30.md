# 1.0.0-beta.30 — One broken piece no longer takes the app down

Until now, if any one part of the screen hit an error while drawing (a pane, a menu, a small
pop-up in the editor, a dialog), the whole window was replaced by the "Something went wrong"
screen and you had to reload. An early beta crash was exactly that: a menu failed and took
everything with it. From this release, a failure is contained to the piece that failed.

## What's new

- **A pane that fails shows a message in that pane only.** The sidebar, the top bar, the tab
  strips and any other panes keep working. The message has **Try again** and **Report this**;
  you can also just close the tab or switch to another one, which clears it.
- **A menu or pop-up that fails simply closes.** Right-click menus, the date menu, the month
  picker, the editor's link box, link preview and formatting bar.
- **A dialog that fails shows a message with Close** instead of blanking the app: Settings,
  Help, Quick capture, Sign-off, the bug report form, the layout dialogs, confirmations.
- **The note editor has its own.** If the editor fails, the note's title and properties stay.
- **Report this** opens the bug reporter with the failure already described.

You should never see any of this in normal use. It only changes what happens when something
goes wrong.

## What to test

- Use the app normally: open and close menus, dialogs, Settings, Help, Quick capture, the layout
  dialogs; open several panes. Everything should look and behave as before.
- If you do see a "…couldn't be shown" message anywhere, press **Report this**. That is a real
  bug we want to hear about, and the rest of the app should still be usable while you report it.

## Known issues

- The command palette is not yet contained this way; an error inside it still reaches the
  whole-window screen. It follows in the next release.
- The open items from beta.19 still stand.
