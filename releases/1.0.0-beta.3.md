# 1.0.0-beta.3 — habit steps, a record of what happened, and a look you can choose

Four things in this release. The app finally wears its own name and mark — the rail had been
showing "Archive" since before the rename. Habits with steps work end to end: you could always
add steps to a habit, but nothing in the app ever let you tick one off. Hollow now shows you its
own record of what you changed, which is mostly useful when something goes wrong. And Appearance
grew up: eight themes instead of four, a separate accent colour, and a way to make the whole
window bigger or smaller.

## What's new

### The app knows its own name

- **Hollow's mark and name now appear in the app.** The left rail showed a letter tile and the
  word "Archive" — a name from two renames ago — and the sign-in screen was titled "The
  Archive". Both now carry the Hollow mark and the Hollow name. The mark picks up your theme's
  accent, so it is gold by default and changes with the accent you choose.
- **A new install opens in the Hollow theme**, the ink-and-gold palette the app icon uses,
  instead of the old violet default. If you have already picked a theme, nothing changes — your
  choice is remembered.

### Appearance

- **Eight themes.** Slate · Amber joins the picker, along with three new ones: **Sage** (green),
  **Carbon**, whose dark mode is pure black and suits OLED screens, and **High contrast**, which
  pushes text and edges as far apart as they go. Newsprint has been dropped — its accent and its
  overdue colour were the same red, so you could not tell a promoted task from a late one.
- **Accent colour is now yours to pick.** Eight accents — amber, olive, green, teal, sky, blue,
  indigo and plum — recolour links, selection and task chips over whatever theme you are using,
  so the four palettes you liked are now thirty-two combinations. The first swatch puts the
  theme's own accent back. Every combination is checked for legibility before it ships.
- **Interface size.** Settings → Appearance → **Interface size** scales the whole window — text,
  icons and spacing together — from 80% to 150%. This is the one to reach for if Hollow reads too
  small on a big monitor. It stays on the computer you set it on rather than following your
  account to your other devices, because it is about the screen you are sitting at. **Editor →
  Font size** still changes note text on its own.

### Habits with steps

- **Steps open in the day's list.** In a day's task list — the Tasks tab beside a note, or beside
  a journal day you have not written yet — a habit with steps now shows a `1/3` count and a
  chevron, exactly like a task. Expand it and tick the steps off for that day.
- **Ticks belong to the day, not the habit.** Yesterday's stay on yesterday.
- **Cadence left the habit row.** "Daily" and its friends no longer clutter the day's list.
  Cadence is shown and edited in the habit editor, which is now one click away.
- **Clicking a habit opens its editor in the sidebar**, the way clicking a task does, instead of
  throwing you over to Planner. **open in Planner ›** still takes you to the Habits tab with that
  habit selected.

### The activity log

- **Settings → Activity log.** Everything Hollow has recorded for your account, newest first,
  across every device: tasks, habits, notes, folders, templates and projects created, edited,
  moved, completed or deleted. Search it, filter it by kind, and narrow it to today, 7 days, 30
  days or everything kept.
- **Copy as markdown and Export JSON.** Both take whatever you have filtered down to, not the
  whole log, so filter first and paste straight into a bug report.
- **The Settings window is wider.** It grew so the log reads on one line instead of wrapping
  every entry. Other sections are unchanged apart from having more room around them.
- **Retention moved.** How long history is kept is now at the bottom of Settings → Activity log,
  next to the log itself, instead of under Data. The setting and its default (90 days) are
  unchanged.

Note text is never recorded, here or anywhere in the history. An edit to a note's body shows as
*edited* with a word count like **+30 words** — never the words. The same goes for task and
project descriptions.

### Bug reports know more

- **Reports carry your last 40 actions and, when sync is unhappy, why.** You no longer have to
  remember what you were doing when something broke. **Show attached context** in the reporter
  shows you exactly what goes with it before you send. Settings → About also has **Copy sync
  diagnostics** if you want to paste the sync side of it in by hand, and sync failures are now
  written to a log file whose path is shown right there.
- **Sync stops crying wolf.** A passing network hiccup used to announce "Sync stalled — changes
  on this device are not uploading" even though the retry had already succeeded. Only a genuinely
  stuck queue says that now; a blip just reads "Syncing…".

## What to test

1. **The sign-in screen and the rail.** Sign out (or start a fresh profile) and check the gate
   screen reads "Hollow" with the ring mark beside it. In the app, check the rail's mark and name
   look right in both Light and Dark — the mark is drawn from your text colour, so it should never
   vanish into the background.
2. **Every theme, both modes.** Walk the eight themes in Light and then in Dark and look for
   anything unreadable — faint metadata, a border that vanishes, a chip whose text disappears.
   Carbon and High contrast are the new extremes, so give those the hardest look.
3. **Accents.** Pick a few accents against a few themes. Check that links, the selected row in a
   list, and task chips all move together, and that overdue items still read as clearly different
   from accented ones. Then press the first swatch and confirm the theme's own accent returns.
4. **Interface size.** Set it to 80% and to 150%, and in each case check the rail, the topstrip
   and a note page still lay out sensibly. Then **close and reopen Hollow** — it should come back
   at the size you chose, without a visible jump from 100%.
5. **Habit steps, end to end.** Create a habit, add two or three steps in the habit editor, then
   find it in a day's list. Check the count and chevron, tick a step, then step to another day and
   confirm it is *not* ticked there.
6. **Clicking a habit.** Click a habit's name in a day's list and confirm its editor opens in the
   sidebar rather than jumping you to Planner. Then try **open in Planner ›**.
7. **Does the activity log match what you did?** Open Settings → Activity log after a normal half
   hour of use. Every task you completed, note you edited and folder you moved should be there,
   named correctly, at the right time. Things you deleted should still show their old name.
8. **Search and filters.** Search for a note by name; search for `doing` and check you get the
   tasks you moved into Doing. Switch between Tasks / Notes / Folders / Projects / Templates.
   Change the range to Today and to Everything kept.
9. **Copy as markdown.** Filter to something small, press it, and paste into a note. It should be
   readable and should say what you actually did.
10. **The bug reporter.** Open it (`Ctrl+Shift+B`), press **Show attached context**, and read the
   recent activity at the bottom. Confirm there is no note text in it. Then send a real report.
11. **Project History still works.** Open any project's History tab. It was rebuilt on the same
   code as the new activity log, so check it reads exactly as it did before — same names, same
   folded autosave runs, same change descriptions.
12. **Retention.** Change the window in Settings → Activity log and confirm older entries go, both
   there and in a project's History tab.

## Known issues

- Only the first 300 matching entries in the activity log are drawn. Use the filters rather than
  scrolling if you go past that; the count on the right tells you how many matched.
- The log reads the last 1000 recorded events. If you need to go further back, use a project's
  History tab, which is not capped the same way.
- History syncs between your devices, so a device that has been offline will fill in its entries
  when it catches up. Timestamps are when the change happened, not when it synced.
