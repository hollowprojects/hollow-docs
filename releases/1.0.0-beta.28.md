# 1.0.0-beta.28 — Completing a task no longer stalls saving

This release has one fix that matters and one piece of housekeeping.

## Read this first: the fix

**Completing a task, or ticking a habit, could stall all saving for about two minutes.** The
checkbox looked done straight away, but behind it the save was stuck, and everything you did
next (edits, new tasks, notes) queued behind it. After roughly two minutes the stuck save gave
up, the task went back to not-done, and the queued changes then went through or failed.

If you have seen tasks "un-complete" themselves, edits that took minutes to stick, or a sync
indicator that sat on pending changes after ticking something off, this was the cause. It has
been in every beta. It is fixed: completion now saves immediately and nothing queues behind it.

It was found by a new automated check that drives the real app instead of a simulated database,
and there is now a test that fails if this kind of stall is ever reintroduced.

## What else changed

- Under the hood, the code that works out habit streaks and the overall streak moved out of the
  (very large) task service into its own service with its own tests. Streak numbers are computed
  by the same rules as before.

## What to test

- **Complete a task** in Planner → List, in the Calendar, in the Day companion and in a project's
  Tasks tab. In each place, immediately afterwards add another task or edit a note, and check
  the change saves at once. Reload and check the task is still done.
- **Tick a habit** for today in Habits and in the Day companion; untick it. Each should stick
  straight away.
- Complete a repeating task and check the next occurrence appears.
- If you are signed in: complete a task on one device and check it arrives on the other.
- Open Habits, note a streak, tick today and check it rises by one; untick and check it falls.

## Known issues

- None new. The open items from beta.19 still stand.
