# 1.0.0-beta.33 — Under the hood: how changes get checked from now on

Nothing in the app changes. This release writes down, and partly automates, how every future
change to Hollow is checked before it reaches you. It is the last part of the housekeeping that
followed the 1 October code review.

## What's new

- Nothing visible in the app.

## What changed underneath

- **A written "definition of done"** for every change: the automated checks pass, behaviour
  changes have a test, and anything that touches the screen or the layer beneath it is run once
  in the real app. That last rule exists because the two worst bugs of this cycle (a crash on
  every screen, and task completion stalling all saving) were invisible to the automated tests
  and were only caught by driving the real app.
- **A review checklist and a pull-request template**, so a change that touches the database, the
  sync rules or the app's foundations is checked by the build server before it is merged, not
  after.
- **A regular health check.** A script now measures the things the code review measured by hand
  (oversized files, unused code, silent failures, slow or fragile tests) so drift shows up as a
  number that moved, and the first dated check is recorded.

## What to test

- Nothing specific. Use the app as usual and report anything that worked in beta.32 and does
  not now.

## Known issues

- None new. The open items from beta.19 still stand.
